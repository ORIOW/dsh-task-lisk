## 1. 背景（自包含；你没有 DSH 侧上下文，读完这节就够）

`dsh-task-lisk` 是已安装上线的 DSH Desktop 插件，两个半身：宿主 `lib/index.js`（任务领域 + `task_lisk` 工具 + 10 个 RPC 端点）、浏览器 `lib/client.js`（界面）。本任务**只动浏览器半身**。

上一个探针任务（`2026-10-27-001`）已从 `app.asar` 源码逐条证实并被我方抽查复核，结论如下（行号均为实测）：

| # | 结论 | 证据 |
|---|---|---|
| 1 | 两个席位都是 **`kind:"list"`**，每条注册必须有 **`id`**；复用已存在的 id 会**替换**该格，新 id 并排追加 | `dsh-client-ui-slots/lib/index.js:181-186` |
| 2 | entry 字段白名单**包含 `inject`**：`{key,id,order,label,priority}` + `select/inject/children/store/locale/registrant` | 同上 `:204-219`（`:214` 即 inject） |
| 3 | **per-entry `inject` 的结果直接作为组件 props**：合成顺序 `{...kit, ...injected, ...slotInjected.props, ...contextual, ...ownerProps}`，**ownerProps 最后、获胜**；`inject() → { hooks: {...} }` 里的 `hooks` 子对象会转成 `use<Name>` Hook props，其余键原样变 props | `dsh-client-ui-renderer/lib/client.js:784-790`（注释 `:769-771`「owner props (owner wins)」） |
| 4 | **组件拿不到 ctx**：渲染机只用合成 props 调用组件。所以「在组件里读 `ctx.connection.rpc`」不可行 | 同上 `:784-790` |
| 5 | `sidebar.footer.action`：list、scope root；owner 只给 **`{wide: boolean}`** 一个 ownerProps（`false` = 56px rail）；**整条容器链没有任何 onClick，按钮 DOM/aria/点击全归 occupant** | 目录 `dsh-cordis-client-runner/lib/client.js:5652-5697`；渲染点 `dsh-client-ui-sidebar/lib/client.js:402-412`；wide 判定 `:225` |
| 6 | `shell.overlay`：list、**ownerProps 为空**；层本身 `pointer-events:none`，`.overlayLayer>*{pointer-events:auto}` ⇒ **occupant 根元素是一个普通盒子就自动可交互**；但**不要把根元素铺满全屏**（会重新挡住整个 app） | 目录 `runner:5433-5490`；CSS 在 `dsh-client-ui-layout/lib/client.js:73`：`.pI_x6G_overlayLayer{z-index:20;pointer-events:none;position:absolute;inset:0}.pI_x6G_overlayLayer>*{pointer-events:auto}` |
| 7 | list 渲染按 **`order` 升序稳定排序**（决定 DOM 序）；`priority` 由运行期强制覆写，**插件传了无效**，排序只用 `order` | `renderer:1203-1218`；覆写见 `runner:275-280` |
| 8 | **动态包里 `window.setInterval` 被扣留并重定向**（`runner:682-684` 原文点名），必须用 `ctx.interval`；而 timer verbs 要求插件级声明 `"timer"`（`runner:347`） | 同左 |
| 9 | 插件对象上的 `inject: ["slots","connection"]` 是**服务声明数组**（门面准入），与注册项里的 `inject: () => ({...})`（props 工厂）**不在一个层面，都要有** | `runner:328-357`、`:596-601`、`:627` |

### 3.3 未完成数徽标（按钮与浮动窗共用）

- 数据源**复用现有** `call(rpc, "list", {})`（`client.js:303` 已在用），**不要新造方法名、不要新增 RPC 端点**。
- 口径：与看板列表摘要一致，**含子任务**；`status === "done"` 不计。若文件里已有现成的计数/摘要函数，**复用那一份**，不要出现第二份口径。

- 显示：`0` 时**不渲染徽标**；`>99` 显示 `99+`。

### 3.4 `sidebar.footer.action` 按钮

```
id: "dsh-task-lisk"   order: 20   label: "任务"
inject: () => ({ rpc: connection.rpc, pending })
```

- `wide === false`（56px rail）：只画内联 SVG 图标 + `aria-label="任务（N 未完成）"`；
- `wide === true`：图标 + 文本「任务」；
- **点击 = 切换**：窗开着 → 关；关着 → 打开并复现上次位置。
- `order: 20`（排在官方 `cordis-panel` 之后）。

### 3.5 `shell.overlay` 浮动窗

```
id: "dsh-task-lisk.float"   order: 100   label: "任务看板"
inject: () => ({ rpc: connection.rpc, pending })
```

- `position: fixed`；内容 = 现有 `TaskBoard`（`:267`，props 只吃 `rpc`）；
- **拖拽只认标题栏**；右下角 16×16 手柄缩放；**最小 320×240**；拖出视口后自动夹回（至少留 48px 可见）；
- 根元素**不要铺满全屏**（见 §2 第 6 条），窗口自身给 `zIndex`（层内局部值，如 30）双保险；
- **不做**吸附、最小化、全局快捷键；
- 指针事件用**元素级** `setPointerCapture` + 元素自身 `pointermove/pointerup`；**不要用 `window.addEventListener`**（与 `window.setInterval` 同属被扣留风险面，见 §2 第 8 条）；
- 关闭方式**只有两种**：标题栏 `×`、侧栏 footer 按钮。**点击外部不关闭**。

## 8. 环境坑（上次同环境实测，能省你半小时）

3. `node` 必须用上面那条 **Electron 版**（`harness\.desktop-bin\node.cmd`）；PATH 里的 node v26 **读不了** `app.asar`。
4. 不要对 `app.asar` 本体调 `fs.openSync`（会 ENOENT），也不要自写 asar 解包器——Node 侧直接 `fs.readFileSync('…app.asar/node_modules/…')` 即可。
5. 本机 `bash` 执行器故障（`CreateFileMapping` Win32 error 5），**用 PowerShell**。
6. 本任务**不需要读 asar**（契约已在 §2 给全），只改工作区里的明文文件。
