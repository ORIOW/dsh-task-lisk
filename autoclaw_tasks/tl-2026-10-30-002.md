## 3. 改动清单（逐条实现，别自行增删）

### 3.1 F2 · 分组判定（容器宽度阈值 480px + 手动三态覆盖）

- **判定基准是浮动窗自身的实测宽度**（拖拽/缩放后的 `w`），**不是** `window.innerWidth`。
- `容器实测宽 < 480px` → **按会话分组**；`≥ 480px` → **保持扁平**。
- 另给**手动三态覆盖**：`自动` / `扁平` / `分组`。用户显式选择后**覆盖**自动判定（选「自动」才回到按宽度判定）。
- 三态选择**持久化**：复用现有 localStorage 键 `dsh.task-lisk.float.v1` 里已有的 `groupMode` 字段（值域从现在的只写 `"auto"` 扩为 `"auto" | "flat" | "grouped"`）。**`groupMode` 从「只存不读」改为「读」**（`:792` 那条注释同步改掉）。
- 默认宽 380 ⇒ **装完第一眼即分组视图**（用户已确认接受）。
- 三态选择器放哪：放在看板工具栏（与现有筛选/刷新同一行），**不要**塞标题栏。

### 3.2 F2 · 分组渲染

- **组头 = 会话标题**（从会话标识取标题；**取不到就回退 `shortId`**）。
- **无 `sessionId` 的任务归「未分组」**，**置底**且**始终显示**（不折叠、不受「未分组」折叠影响）。
- 组内排序：沿用 `order`，再按优先级/截止（**复用现有排序口径**，不要新造第二套）。
- **组可折叠**；折叠态**持久化**（新键 `dsh.task-lisk.float.collapsed.v1`，值 `{ [sessionId]: true }`，**全局一份**，与 `float.v1` 的全局口径一致）。
- **不过滤**：分组只是视觉重排，不隐藏任何任务。
- **当前会话组高亮**：左侧色条 +「当前」小标签（实现前提见 §3.3）。

### 3.3 F2 · 「当前会话标识」——**本批唯一的设计未知项，必须先实证**

**问题**：客户端 `apply(ctx)` 目前只用 `ctx.connection` / `ctx.effect` / `ctx.interval` / `ctx.slots`（`:1150-1175`），**拿不到会话对象**；宿主 `list` 响应也不含当前会话标识（`index.js:594-608`）。而 F2 要「高亮当前会话组」，3.2 要「UI 建任务写当前会话」，两者都必须先知道「当前会话 id（最好还有标题）」。

**候选来源（按优先级逐个实证）**：

| 优先级 | 来源 | 说明 |
|---|---|---|
| A | 客户端 **`ctx.sessions`** 服务 | 客户端平台服务目录里**存在**键 `sessions`（方法 `retain / using / retainInfo / refreshProjections / search / fork / scope / binding`）。harness 自己判「当前会话」的口径是 **`sessions.retainInfo(id).getSnapshot().retainedBy.mainView > 0`**（本机 `research/reminders/float-ball/package/CHANGELOG.md` 与 `research/todoboard/package/CHANGELOG.md` 均记录此判据）。 |
| B | `ctx.connection` 上是否暴露当前会话标识 | 读 `ctx.connection` 的可用字段，看有没有会话 id / 标题。 |

**必须先做的运行时实证（AutoClaw 有浏览器，这一步不能省）**：

1. 在浏览器里探一次，打印 `Object.keys(ctx)`、`ctx.sessions` 的类型与可用方法、以及（若有）会话列表的形状；
2. 确认能否**稳定拿到「当前会话 id + 标题」**，并记下实际取法；
3. 把实证结论（含你实际打印到的形状原文）写进结果 MD 的 `evidence`。

**硬规则**：

- **绝不臆造 sessionId**。拿不到就**不实现高亮**（也不给新建任务写 sessionId，保持 `null`），并在结果 MD 里写 `status: needs-input` + 说明缺什么、你验证过哪些来源。
- 若走来源 A，插件级 `inject` 数组要**加 `"sessions"`**（`:1144`），**保留 `"timer"`**（`verify-bundle.mjs` D6 断言要求 inject 含 `timer`，只增不改）。
- 若为了拿当前会话**必须改 `lib/index.js`**（比如要在 `list` 响应里加当前会话字段）⇒ **不要改**，直接 `status: needs-input` 报回，等 DSH 侧决定。
- 「UI 建任务写当前会话」：拿到当前会话 id 后，在 `:293` 那条通用 `call` 的 payload 里**带上 `sessionId`**（宿主 `:444` 已支持）；拿不到则保持不写。

## 8. 环境坑（上次同环境实测，能省你半小时）

1. **你的执行沙箱会把 `%APPDATA%` 重定向到工作区内部**——凡是要碰 DSH 数据目录，一律写绝对路径 `C:\Users\A005490\AppData\Roaming\dsh-desktop\...`，不要用 `$env:APPDATA`。
2. **PowerShell 5.1 向 `node.cmd`（批处理包装）传含 `|` 的参数会被 cmd 二次解析成管道**——正则里避开 `|`，或把模式拆成多次执行。
3. `node` 必须用上面那条 **Electron 版**（`harness\.desktop-bin\node.cmd`）；PATH 里的 node v26 **读不了** `app.asar`。
4. 不要对 `app.asar` 本体调 `fs.openSync`（会 ENOENT），也不要自写 asar 解包器——Node 侧直接 `fs.readFileSync('…app.asar/node_modules/…')` 即可。
5. 本机 `bash` 执行器故障（`CreateFileMapping` Win32 error 5），**用 PowerShell**。
6. 本任务**不需要读 asar**（契约已在 §2 给全），只改工作区里的明文文件；§3.3 的实证用**浏览器**做，不要用 node 读 asar 猜。
