## 3. 改动清单（逐条实现，别自行增删）

### 3.1 P1 · `task_lisk` 工具输出带 `sessionId`

1. `output.schema.properties.tasks.items.properties` 里，在 `repeat` 之后追加：
   ```js
   sessionId: { type: "string", required: true }
   ```
   （沿用现有写法：**null 也要给字符串**，空串表示「无会话」，不要给 `null` 也不要 optional。）
2. `render(records)` 里在 `repeat: t.repeat` 之后追加：
   ```js
   sessionId: t.sessionId ?? ""
   ```
3. `action === "list"` 的 summary：**每条任务行尾**加 sid 片段，仅当非空时追加，形如：
   ```
   - [todo] 修登录 (tl_ab12cd) high due=2026-11-05 sid=session-3
   ```
   口径：`sid=<sessionId 前 8 位>`（复用 `shortId` 同款截断口径即可，宿主半身里没有 `shortId`，就地写 `t.sessionId.slice(0, 8)`；**不要**把完整 sessionId 塞进 summary，太吵）。**只改 list 分支的 summary，其它 action 的 summary 一个字都不要动。**
4. 不要改工具描述、参数、其它 action 的返回结构；不要新增 RPC 端点。

### 3.2 P2 · 每日首访未完成任务提示（四个口径**已钉死**）

**口径 1 · 触发时机**：**当天第一次打开浮动看板**时判定（TaskBoard 挂载 → 首次 `loaded === true` 时判定一次）。用**本地日历日** `YYYY-MM-DD` 作为「一天」的单位。**不做**定时器、**不自动打开看板**、**不发系统通知**、**不发任何 RPC**。

**口径 2 · 展示面**：渲染在**浮动看板内部、看板内容之上**——即 `TaskBoard` 返回的根节点（flex column）的**第一个子元素**，位于工具栏/筛选行之上的一条独占行横幅，`key: "nudge"`，`role: "status"`，`aria-live: "polite"`。不要新开 `shell.overlay` 席位、不要做成模态框、不要盖住帮助浮层。

**口径 3 · 免打扰**：**仅当**「当天还没提示过」**且**「未完成任务数 > 0」时出现。判定基准 = 当天本地日期 ≠ localStorage 里记录的日期。**展示即视作已提示**（出现时就写盘；用户看没看都算当天已提示，避免同一天反复打扰）。点「知道了」只隐藏当前横幅，不再写盘。**当天没有未完成任务时不显示、也不写盘**（这样当天后来新建了任务，再打开还会正常提示）。「暂停/硬停」策略不影响本提示。

**口径 4 · 去重与持久化**：新键 `NUDGE_STORAGE_KEY = "dsh.task-lisk.nudge.v1"`，值形如 `{"date":"2026-11-01"}`，**全局一份**（与 `float.v1` 的口径一致，不按会话分）。读写全部 `try/catch`（localStorage 可能被禁用/抛错，失败就当从未提示过且不影响看板渲染）。**不写 storage domain、不改任务数据、不发 RPC**。

**实现要点（照这个拆，便于 smoke 覆盖纯函数）**：

1. 在 `COLLAPSED_STORAGE_KEY`（`:245`）附近定义 `NUDGE_STORAGE_KEY`。
2. 新增 3 个**纯函数**（放模块级，不依赖 React）：
   - `todayKey(now = new Date())` → `"YYYY-MM-DD"`。**必须用 `getFullYear()/getMonth()+1/getDate()` 补零拼接，不要用 `toISOString()`**（会被 UTC 时区拉偏一天）。
   - `nudgeNeed(saved, today, pendingCount)` → boolean：`saved?.date !== today && pendingCount > 0`。
   - `nudgeText(pendingCount, overdueCount)` → 文案：基础句 `今天还有 N 个未完成任务`；`overdueCount > 0` 时追加 `，其中 M 个已逾期`；末尾不加标点句号以外的装饰。
3. 新增 `loadNudge()` / `markNudge(today)`（`try/catch` 包住 localStorage 读写，风格抄 `:295` / `:312`）。
4. `TaskBoard` 内：
   - 新增 `const [nudge, setNudge] = useState(null)` 与 `const nudgeChecked = useRef(false)`；
   - 新增一个 `useEffect`：当 `loaded === true && !nudgeChecked.current` 时判定一次（置 `nudgeChecked.current = true`）：算 `pendingCount = countPending(tasks)`、`overdueCount = tasks.filter(t => t.status !== "done" && t.dueAt !== null && isFinite(Number(t.dueAt)) && Number(t.dueAt) < Date.now()).length`（`dueAt` 在 RPC 响应里是 **epoch 毫秒数字**，可能是 `null`）；若 `nudgeNeed(loadNudge(), todayKey(), pendingCount)` → `markNudge(today)` 且 `setNudge({ pending: pendingCount, overdue: overdueCount })`。
   - 根节点 children 最前面插横幅（`nudge === null` 时为 `null` 或直接不插），右侧按钮文案 `知道了`（`title:"知道了"`、`aria-label:"关闭每日提示"`），`onClick: () => setNudge(null)`；样式复用 `S` 里既有对象 + `var(--dsw-alias-*)` 变量（建议浅底 + 左侧强调色，别用红色警告配色）。
5. `__internals` 追加导出：`todayKey`、`nudgeNeed`、`nudgeText`、`NUDGE_STORAGE_KEY`。
6. **不要**给侧栏按钮加额外角标/圆点（它已有未完成数徽标），不要改浮动窗几何/拖拽/缩放/帮助逻辑。
